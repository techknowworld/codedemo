JulesCare conceptual architecture

Rules decide eligibility. AI drafts and explains. People approve. The diagram shows how a provider's organization-level need becomes a human-approved, payment-blind shortlist, and where each trust boundary sits.

Deterministic component Human actor / authority AI (sandboxed, no authority) Untrusted or isolated Trust boundary

Payment-blind matching

Commercial accounts sit in an isolated store with no read path from the matching engine or the AI sandbox (BR-01, NFR-03, test T03).

AI behind a hard boundary

Per ADR-0001 the LLM never holds a connection string. It calls typed tools on the MCP server, which applies org_id and read-only views; output fails validation if a claim lacks an evidence ID (REQ-05).

Tenant isolation

Needs, match runs, shortlists and approvals live in the tenant plane under row-level security. Evidence is shared across tenants in the CareTech Compass catalog (AS-01, NFR-01).

Humans hold authority

Reviewers approve the need, the criteria and the shortlist. The approval gate only moves a shortlist to approved on an authorized human event (REQ-06).

Reproducible decisions

The audit spine is append-only and hash-chained. Each match run pins requirement, evidence, rules and model/prompt versions so a past shortlist can be rebuilt (NFR-04).

Privacy at the door

The intake guard blocks resident names, room numbers and diagnoses before anything is stored, and audit records carry no PHI (REQ-01, NFR-02, test T01).
