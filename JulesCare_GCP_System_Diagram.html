JulesCare on Google Cloud

The same logical architecture with the backend on Google Cloud and the client side kept on the Microsoft stack: Blazor WebAssembly on Azure Static Web Apps, optional .NET MAUI Blazor Hybrid apps, and Microsoft Entra for sign-in. The .NET monolith, AI worker and MCP server run on Cloud Run inside a VPC Service Controls perimeter in Canada.

Client-side components stay on Microsoft. Everything behind the API moves to Google Cloud.

Cross-cloud seams

Two consoles, two IAM models and two bills. Keep the seam thin: the only cross-cloud traffic is the browser calling the API with an Entra token. Use Terraform for both clouds and one GitHub Actions pipeline.

Audit without ledger tables

Each audit row stores the hash of the previous row. A scheduled job verifies the chain and writes checkpoints to the locked log bucket.

Why Cloud Run

It matches the modular-monolith decision: containers, revisions and traffic splits without running GKE. Revisit GKE only if the service count or control needs grow.

Check before committing

Confirm that the chosen Vertex AI models, Model Armor and Sensitive Data Protection are available in the Montréal and Toronto regions, and that data-residency terms suit the provider pilots.
