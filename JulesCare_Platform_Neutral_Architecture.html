JulesCare platform-neutral architecture

The system described by capabilities instead of products. Any cloud or data centre that supplies these building blocks, with the same trust boundaries, can host JulesCare. The table below maps each block to Azure, Google Cloud, AWS and self-managed options.

What must hold on any platform

Per-workload identities, private access to every data service, a database with row-level security, a queue with dead letters and an immutable store. If a platform lacks one, the architecture invariants cannot be met there.

Keep the core portable

The application code depends on standards: OIDC tokens, OpenTelemetry, SQL with RLS, AMQP or HTTP messaging, and MCP. Platform-specific pieces sit behind adapters, chiefly the LLM gateway and the PII detector.

Data residency first

Whichever platform is chosen, confirm Canadian hosting for data, backups and model inference before committing, and record the choice as an ADR.
