JulesCare, cloud-agnostic

The same logical architecture built only on open, portable components: containers on any conformant Kubernetes, PostgreSQL, RabbitMQ, S3-compatible storage, Keycloak for sign-in and an open-source LLM gateway that can route to any model provider. It runs on Azure, Google Cloud, AWS, a Canadian sovereign cloud or on-premises, with only the managed-service adapters changing.

Portability has a cost

Running Keycloak, RabbitMQ, Vault and the observability stack yourself adds operations work the Azure and GCP designs avoid. With a 50% DevOps engineer, use the cloud's managed Kubernetes and PostgreSQL, and keep the open components to the few that carry portability.

Portable code, not portable everything

Write the app against standards (OIDC, OpenTelemetry, the S3 API, PostgreSQL, MassTransit) and keep cloud specifics in OpenTofu modules and adapters. The containers and Helm charts stay identical; only infrastructure modules change per cloud.

Model choice stays open

The LLM gateway lets the pilot switch between hosted models or a self-hosted model under vLLM for data residency. Every switch must pass the full evaluation harness, including the injection and grounding suites, before release.

Check before committing

Confirm Canadian-region availability for the chosen model provider, guard model licence terms, and whether Presidio's health recognizers need custom patterns for long-term-care terms. Without ledger tables, the hash-chained audit is the app's job and needs its own tests.
